# moonlight-local-cursor

Курсор як у Steam Remote Play для трансляції ігор **Sunshine → Moonlight** на Linux. Курсор гри малює сам клієнт,
рідним курсором системи, тому він рухається миттєво. З відео ПК курсор прибирає, тож на екрані він один.

[English](README.md)

## Навіщо

Moonlight показує курсор ПК як частину відео. Кожен рух мусить дійти до ПК і повернутися закодованим кадром, тому
курсор відстає на всю затримку трансляції. На каналі 100–200 мс у рольовках, стратегіях і всьому, де є курсор, грати
боляче. Вбудований у Moonlight «локальний курсор» лише додає другу стрілку поверх тієї, що відстає.

Steam Remote Play передає клієнту *форму* курсора, і клієнт малює його сам. Цей проєкт робить те саме для Sunshine
і Moonlight, коли ПК працює на Linux.

- Курсор рухається без затримки трансляції, бо його малює сам клієнт.
- Форма справжня, з гри: меч, рука, діалог, з правильною точкою кліку.
- Розмір — як у трансляції, але не менше 24 px: курсор 32 px з 4K-ПК у вікні 1080p не стає крихітним.
- Курсора ПК у відео нема, тож не буде двох курсорів.
- На клієнті нічого налаштовувати не треба: помічник сам знаходить вікно трансляції, а адресу ПК бере з налаштувань
  самого Moonlight.
- Заодно лікує смикання «кадр вперед, кадр назад» при русі камери, яке буває з KMS-захопленням Sunshine (див.
  [Крапка проти прямої віддачі кадру](#крапка-проти-прямої-віддачі-кадру)).

## Як це працює

- **ПК** (`host/mlc-host.py`) читає X-курсор через XFixes і шле кожну нову форму один раз, далі лише її номер. Поки
  підключений хоч один клієнт, курсор над X-вікнами схований (`XFixesHideCursor`). XWayland віддає композитору
  порожній курсор, і в захоплення Sunshine він не потрапляє, хоч би як композитор його малював. Відключився останній
  клієнт або зупинилась служба — курсор повертається сам.
- **Клієнт** (`client/mlc-client.py`) — чистий Python, libX11 і libXcursor через ctypes. Курсор малює X-сервер
  клієнта. Невидиме InputOnly-вікно подій не вибирає, тож клацання й рух доходять до Moonlight як були. Moonlight
  перестворює вікно (зміна рушія, розмір) — помічник переходить у нове.

Протокол — у [PROTOCOL.md](PROTOCOL.md), він маленький, клієнт під Windows, macOS чи Android написати нескладно.

## Що потрібно

**ПК:** Linux і Sunshine; ігри з X-курсором (усе під XWayland: Proton, Wine, більшість нативних під X11); Python 3 з
`python-xlib`; користувацька сесія systemd.

**Клієнт:** Linux і Moonlight (звичайний, Flatpak або AppImage) під X11 або XWayland; Python 3, `libX11`,
`libXcursor`. Moonlight має бути в **абсолютному режимі миші**: *Налаштування → Optimize mouse for remote desktop
instead of games*.

## Встановлення

```bash
git clone https://github.com/PiGYk/moonlight-local-cursor.git
cd moonlight-local-cursor
```

**На ПК** (де Sunshine):

```bash
./install.sh host                    # слухає 0.0.0.0:48100, пускає лише приватні адреси й localhost
./install.sh host --output DP-1      # якщо Sunshine транслює не основний монітор
./install.sh host --listen 10.0.0.2 --allow 10.0.0.7/32    # один клієнт і лише через адресу VPN
```

Ставиться служба `moonlight-local-cursor-host`. Якщо Sunshine працює як користувацька служба, наша стартує й
зупиняється разом з ним. У брандмауері відкрийте TCP-порт 48100 для своїх клієнтів; команду для firewalld і ufw
установник покаже.

**На клієнті** (де Moonlight):

```bash
./install.sh client --absolute-mouse         # ще й вмикає абсолютний режим миші (спершу закрийте Moonlight)
./install.sh client --xwayland               # у сесії Wayland: Moonlight запускатиметься під XWayland
./install.sh client --host 192.168.1.50      # лише якщо ПК недосяжний за адресою, яку знає Moonlight
```

Помічник стартує разом із сесією й чекає трансляції. Далі просто грайте як завжди.

Видалити: `./install.sh uninstall host` або `./install.sh uninstall client`.

## Крапка проти прямої віддачі кадру

Коли курсор схований, на моніторі може лишитися саме вікно гри на весь екран. Тоді композитор може віддавати буфери
гри прямо на екран (direct scanout), не складаючи кадр сам. KMS-захоплення Sunshine читає буфер з площини екрана, а
гра вже малює в нього наступні кадри, тож при русі камери трансляція смикається на кадр вперед і назад.

Ми впіймали це на labwc (wlroots 0.20) з NVIDIA: раніше пряму віддачу блокував видимий програмний курсор, а коли його
сховали, вилізла проблема. Тому, поки є клієнти, ПК тримає в куті монітора трансляції вікно 1×1 з прозорістю 1/255.
Його не видно, клацання проходять крізь нього, фокус воно не бере, а композитор знову складає кадр сам. Перевірити
можна в `/sys/kernel/debug/dri/*/state`: без крапки основна площина монітора крутить буфери гри (у нас 5), з крапкою
— буфери композитора (2). Вимкнути: `--no-scanout-blocker`.

## Обмеження

- Лише X-курсори. Нативні Wayland-програми на ПК мають курсор композитора, і він лишається у відео.
- Клієнт працює з X11. У сесії Wayland Moonlight має йти під XWayland (`--xwayland` це налаштує).
- Лише абсолютний режим миші. Ігри, що захоплюють мишу для огляду камерою, потребують відносного режиму: Moonlight
  перемикається Ctrl+Alt+Shift+M, але тоді локальний курсор розходиться з ігровим. Steam перемикає сам, Moonlight так
  не вміє без власних змін.
- Схований курсор — для всіх клієнтів одразу, зокрема й для тих, хто без помічника.
- Клієнтів під Windows, macOS, Android та iOS ще нема. Ігровий режим Steam Deck не перевіряли.

## Безпека

Бічний канал несе лише картинки курсора й пінги: ні вводу, ні вмісту екрана. Шифрування й паролів нема, тож тримайте
його в локальній мережі або VPN. За замовчуванням ПК пускає лише приватні адреси й localhost; звужуйте через
`--listen`, `--allow` і брандмауер.
